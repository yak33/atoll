# 02 · 架构设计

> 状态:v0 草案 · 2026/09/30 · 作者 ZHANGCHAO

## 1. 总体分层

```
┌─────────────────────────────────────────┐
│  UI 层(src/*.vue)                        │
│  三态状态机 / 进度条 / 倒计时(本地时钟)      │
├─────────────────────────────────────────┤
│  core 层(src/core/,M1 落地)              │
│  轮询调度 / TTL 缓存 / 抖动 / 指数退避      │
├─────────────────────────────────────────┤
│  adapter 层(src/adapters/)               │
│  zhipu.ts:URL 与请求头构造、响应解析(纯函数)│
├─────────────────────────────────────────┤
│  网络层(tauri-plugin-http,M1 引入)        │
│  走 Rust 侧发请求,绕开 WebView 的 CORS    │
├─────────────────────────────────────────┤
│  Tauri 壳(src-tauri/)                    │
│  窗口形态配置,零业务逻辑                   │
└─────────────────────────────────────────┘
```

依赖方向单向向下:UI → core → adapter → 网络。UI 不 import adapter、不出现平台专有字段名;adapter 不知道 UI 存在。

## 2. 统一数据模型(src/types.ts)

```ts
type WindowKey = '5h' | 'weekly'

interface UsageWindow {
  key: WindowKey
  usedPercent: number    // 已用百分比,0~100+,上游超卖不裁剪,由 UI 决定显示策略
  resetAt: string | null // RFC3339;null = 上游未下发重置时间
}

interface ZhipuQuotaSnapshot {
  planLevel: string                      // data.level,套餐档位
  windows: UsageWindow[]                 // 通常 2 档(5h + weekly)
  source: 'tokens_limit' | 'credit_limit' // 见接口文档 §4,降级时 UI 可标注
  fetchedAt: string                      // 本地落快照的时刻(RFC3339)
}
```

后续扩展新平台(如 Claude)时:新 adapter 输出自己的快照类型,UI 侧按模块渲染,互不污染——这是「灵动岛容器」的扩展点。

## 3. 网络层设计(M1)

**为什么不能直接用浏览器 `fetch`**:WebView 里请求 `open.bigmodel.cn` 属于跨域,官方接口不会返回 CORS 头,请求会被拦。Tauri 2 的官方解法是 `tauri-plugin-http`,请求经 Rust 侧发出,不受 WebView 同源策略约束。

引入方式(三个位置同步改):

1. `src-tauri/Cargo.toml` 加 `tauri-plugin-http = "2"`;`lib.rs` 注册 `.plugin(tauri_plugin_http::init())`
2. `package.json` 加 `@tauri-apps/plugin-http`
3. `src-tauri/capabilities/default.json` 加权限,并把允许的域名收紧到白名单:

```json
{
  "identifier": "http:default",
  "allow": [
    { "url": "https://open.bigmodel.cn/*" },
    { "url": "https://api.z.ai/*" }
  ]
}
```

> ⚠️ M1 落地时以 [tauri-plugin-http 官方文档](https://v2.tauri.app/plugin/http-client/) 的权限 schema 为准,此处写法若有出入以官方为准。

## 4. core 层设计(M1)

一个 `QuotaPoller` 类即可,不搞订阅总线:

- **轮询周期**:默认 5 分钟(可配 3~10 分钟),每次触发加 0~800ms 随机抖动。
- **缓存**:内存里只存最近一份 `ZhipuQuotaSnapshot` + `fetchedAt`;应用重启后首次展示「无数据」并立即拉一次,不做持久化快照(v0 不需要)。
- **退避**:401/403 → 停止轮询,UI 提示凭据无效(等用户改 Key 才恢复);429/网络失败 → 指数退避(1min→2min→4min,上限 10min),成功后复位。
- **手动刷新**:重置退避并立即拉取,但进行中请求去重(单飞)。

## 5. 凭据存储(M1 决策)

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| localStorage | 零依赖,最简单 | 明文存 WebView profile 目录,换打包方式可能丢 |
| tauri-plugin-store | 官方插件,落到应用数据目录,与窗口生命周期解耦 | 多一个插件依赖 |

**选 tauri-plugin-store**:Key 属于长期凭据,应落在 `%APPDATA%` 应用目录而不是浏览器存储;成本只是一个官方插件。

## 6. 窗口行为(Tauri 侧,现骨架已含)

当前 `tauri.conf.json` 已配置:`decorations: false`、`transparent: true`、`alwaysOnTop: true`、`skipTaskbar: true`、固定尺寸 260×44。后续:

| 能力 | 实现方式 | 里程碑 |
| --- | --- | --- |
| 顶部居中定位 | 启动时读主显示器尺寸,`set_position` 计算居中 | M2 |
| 鼠标穿透 | JS 侧 `getCurrentWindow().setIgnoreCursorEvents(true, { forward: true })`,悬停热区恢复 | M3 |
| 全屏隐藏 | 轮询前台窗口是否全屏(Rust 侧小命令或官方 API) | M3 |
| 开机自启 | tauri-plugin-autostart | M3 |
| 托盘 | tauri-plugin-tray(退出入口) | M3 |

> ⚠️ 穿透/全屏检测的具体 API 签名 M3 时查官方文档确认,不在骨架期臆造。

**Windows 透明窗口注意**:若出现黑底不透明,通常是 WebView2 异常,排查方向:WebView2 版本、`decorations` 是否为 false、显卡驱动;兜底方案是放弃纯透明、用深色圆角实底(视觉差异小)。

## 7. 错误处理约定

错误在 adapter 层转成**带语义的类型**,UI 只按类型渲染:

| 类型 | 触发 | UI 表现 |
| --- | --- | --- |
| `credentialInvalid` | HTTP 401/403 | 「Key 无效」,引导打开设置 |
| `upstreamError` | HTTP 5xx / `success=false` 业务错误 | 「服务异常」,保留旧快照标注过期 |
| `networkError` | 超时/DNS/断网 | 「网络不可达」,退避重试 |
| `parseError` | 字段结构对不上 | 「数据异常」+ console 结构化日志,**这是接口变更的信号** |

`parseError` 是非公开文档接口的变更探测器,必须显式暴露而不是静默吞掉。

## 8. 性能预算

| 项 | 预算 | 手段 |
| --- | --- | --- |
| 常驻内存 | < 60MB | Tauri + WebView2;不引 UI 框架外的大依赖 |
| 空闲 CPU | ~0% | 倒计时用 60s 间隔的单个 `setInterval`;无动画时停止渲染循环 |
| 网络请求 | ≤ 1 次 / 3min | 轮询下限 + 抖动;倒计时纯本地计算 |
| 启动到可见 | < 2s | 无重初始化,窗口直接渲染占位再填数据 |
