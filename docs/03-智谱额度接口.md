# 03 · 智谱额度接口(逆向整理)

> 状态:v0 · 2026/09/30 · 作者 ZHANGCHAO
>
> ⚠️ **这是非公开文档接口**(智谱网页端/官方工具内部使用),没有官方 API 文档保证,字段随时可能变更。解析逻辑全部集中在 `src/adapters/zhipu.ts`,变更时只改一处。行为参考自开源项目 sub2api(`cn_provider_quota_service.go`)与 cc-switch 的同名实现,两家解析规则一致,可信度较高。

## 1. 端点

```
GET https://open.bigmodel.cn/api/monitor/usage/quota/limit
GET https://api.z.ai/api/monitor/usage/quota/limit        # z.ai 国际站,路径相同
```

主机由用户配置的 base_url 推导,规则:

| base_url 含 | 额度主机 |
| --- | --- |
| `bigmodel.cn` | `https://open.bigmodel.cn` |
| `z.ai` | `https://api.z.ai` |
| 其他/未知 | 默认回落国内站 `https://open.bigmodel.cn` |

## 2. 鉴权与请求头

**关键怪癖:Authorization 放裸 API Key,不加 `Bearer ` 前缀。加了会 401。**

```
Authorization: <你的APIKey>
Accept: application/json
Content-Type: application/json
Accept-Language: en-US,en
```

### 团队版(GLM Coding Plan 团队订阅)

个人版凭据不含组织 ID;团队版必须加两样,否则官方返回「当前用户不存在 coding plan」:

1. URL 追加 `?type=2`
2. 请求头:

```
bigmodel-organization: <组织ID>
bigmodel-project: <项目ID>        # 可选,有才发
```

## 3. 响应结构(成功)

```jsonc
{
  "success": true,
  "data": {
    "level": "GLM_CODING_PLAN_MAX",     // 套餐档位,原样展示用
    "limits": [
      {
        "type": "TOKENS_LIMIT",          // 窗口额度条目
        "unit": 3,                       // 3 = 5h 窗口
        "percentage": 43.5,              // 已用百分比(不是剩余!)
        "nextResetTime": 1759250400000   // 毫秒时间戳,或 ISO8601 字符串
      },
      {
        "type": "TOKENS_LIMIT",
        "unit": 6,                       // 6 = weekly(7d)窗口
        "percentage": 12.1,
        "nextResetTime": "2026-10-03T00:00:00Z"
      }
    ]
  }
}
```

字段要点:

- `percentage` 是**已用**百分比,范围可超 100,不做裁剪,由 UI 决定封顶显示(如 `>999%`)。
- `nextResetTime` 两种形态都出现过:毫秒时间戳(数字)或 ISO8601(字符串),解析需兼容;`0`、缺失、无法解析 → 视为「无重置时间」。
- 老套餐可能只回 1 条 TOKENS_LIMIT(仅 5h);新套餐回 2 条。

## 4. 解析规则(顺序敏感)

1. **只认 `type` 为 `TOKENS_LIMIT` 和 `CREDIT_LIMIT` 的条目**,其他 type 忽略。
2. **TOKENS_LIMIT 与 CREDIT_LIMIT 度量不同**(token 窗口 vs 信用额度),两者同时存在时只让 TOKENS_LIMIT 参与窗口归类,避免信用额度百分比污染窗口用量。
3. **窗口归类优先用 `unit` 字段**:`3` → 5h,`6` → weekly。
   - ⚠️ 不能用 reset 时间排序代替 unit 判断:周期末尾时周窗口可能比 5h 更早重置,按时间排序必然标反(这是智谱侧踩过的真实坑,sub2api issue #3036)。
4. **unit 缺失/未识别的兜底启发式**:无 `nextResetTime` 的条目优先归 5h(0% 状态下 5h 桶可能没有 reset),其余按 reset 时间**升序**依次填入仍空缺的槽位。
5. **CREDIT_LIMIT 降级**:仅当响应里一条 TOKENS_LIMIT 都没有时(部分套餐只报信用额度),才用 CREDIT_LIMIT 条目按上述兜底规则展示,并在快照上标记 `source: 'credit_limit'` 供 UI 标注。

## 5. 响应结构(失败)

| 情况 | 表现 | 处理 |
| --- | --- | --- |
| Key 无效 | HTTP 401 / 403 | `credentialInvalid`,停止轮询等用户改 Key |
| 团队版参数缺失 | HTTP 200 + `success: false`,msg「当前用户不存在coding plan」 | `upstreamError`,提示检查组织 ID |
| 业务错误 | HTTP 200 + `success: false` + `msg` | `upstreamError`,原样展示 msg |
| 服务异常 | HTTP 5xx | `upstreamError`,退避重试 |

**注意 `success: false` 藏在 HTTP 200 里**,必须检查 body,不能只看状态码。

## 6. 调用纪律

- 该端点为只读 GET,实测可低频轮询;本项目纪律:**间隔 ≥ 3 分钟 + 0~800ms 随机抖动**,手动刷新受单飞去重。
- 超时 15 秒足够。
- 响应体上限按 256KB 截断防护。

## 7. 变更探测

接口字段变更的第一信号是 `parseError`(结构对不上)。处理流程:对照本档更新字段说明 → 改 adapter → 补解析用例。参考的两个上游项目(sub2api / cc-switch)都在活跃维护,它们对同一接口的解析变更也可作为对照来源。
